MRI-Derived Cardiac Blood-Flow Analysis

A MATLAB workflow for smoothing left-ventricular flow measurements, separating individual cardiac cycles, and estimating the area beneath each flow curve using numerical integration.

Problem and approach

The project used recorded left-ventricular blood-flow measurements from an MRI-derived dataset. Its goal was to visualize the repeated flow waveform and estimate the area beneath each cardiac cycle, an approach that can be used to approximate the volume moved per beat when the input flow units are known.

The workflow begins with a time-and-flow CSV dataset. Gaussian smoothing reduces fluctuations without discarding the original measurements. A peak-detection routine then searches backward to identify troughs, which divide the signal into individual cardiac cycles.

Processing pipeline

Signal preprocessing

MATLAB smoothdata applied Gaussian smoothing with timestamps as sample points and a smoothing factor of 0.25.

Cycle identification

A custom function identified peaks that met the search criteria, then walked backward to the preceding trough to establish cycle boundaries.

Numerical integration

The program removed incomplete boundary cycles and applied trapz to the time and flow vectors for each complete cycle.

Visualization

Four coordinated plots presented the original waveform, smoothed waveform with detected troughs, overlapping individual cycles, and a histogram of their areas.

Results and interpretation

The report recorded a mean area of 98,515.754379 with a standard deviation of 6,070.890172 in the dataset's flow-by-time units. Converting these areas to physiological volume requires confirming the underlying measurement units and any scaling factors. The reported result should therefore not be interpreted as a stroke-volume value in milliliters without that context.

The analysis demonstrates a reproducible route from noisy cyclic measurements to per-cycle numerical summaries, rather than a diagnostic assessment of cardiac health.

MATLAB implementation

The report structures the implementation as a main script supported by processFlow, findTroughs, findCycles, and displayResults. The central integration step is:

for i = 1:length(cycle_times)
    areas(i) = trapz(cycle_times{i}, cycle_flows{i});
end

Further work could improve peak detection in the presence of unusual waveform shapes, make thresholds data-adaptive, and add unit validation before reporting physiological volumes.
